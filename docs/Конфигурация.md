# Конфигурация

Все настройки панели — в `/etc/lan-discovery/settings.json` (JSON). Код содержит
только дефолты; файл — override поверх дефолтов. Правки через вкладку
«Система → Настройки» или руками (затем дождаться перечитывания/рестарта, см.
ниже).

## Как применяются правки

| Тип настроек | Кэш | Когда применяется |
|---|---|---|
| Ленивые хелперы (`_scan_interval`, `_subnet`, self-check, wifi/traffic-интерфейсы, hosts) | 10 секунд | автоматически, без рестарта |
| `web.flask_host` / `web.flask_port` | при старте процесса | `systemctl restart lan-discovery` |

Чтение: `app._cfg(section, key, default)` (кэш `load_settings`, 10 с). Дубли
`load_settings` есть в `core_routes`/`system_routes`/`weather_routes` — читают
тот же файл.

## Секция `network`

| Ключ | Дефолт | Кто читает |
|---|---|---|
| `subnet` | `192.168.3.0/24` | `core.discovery._subnet()` (nmap -sn, фоновый и `POST /api/scan`), `inventory.scan_all_devices()` |
| `scan_interval` | `30` (сек) | `app._scan_interval()`, `core.discovery._scan_interval()` (цикл сканера), `system_routes.page_data()` |
| `scan_enabled` | `true` | `core.discovery._scan_enabled()` — `false` = фоновый скан спит (одна ведущая копия сканера в LAN, PHASE 16 №59; ручной `POST /api/scan` и статус работают). Пример: ведёт X96 → на OP в `settings.json` `network.scan_enabled: false` |
| `scan_ifaces` | `["end0", "eth0", "wlan1", "wlan0"]` | `core.discovery.run_scan()` — перебор интерфейсов nmap до первого успеха (закрывает хардкод wired/wifi-списков) |
| `max_misses` | `6` | `app._max_misses()`, `core.discovery._max_misses()` (переход в offline) |
| `self_ips` | `["192.168.3.234", "192.168.3.235"]` | discovery (всегда «свои»), self-check `/api/monitoring/<ip>` |
| `default_hosts` | `["google.com", "ya.ru", "192.168.3.1"]` | nettools (хосты для проверки связи) |
| `known_web_ports` | `{"192.168.3.234": 8080, …}` | inventory: какие веб-порты пробить у какого IP |
| `web_aliases` | `{"192.168.3.234": "192.168.3.235"}` | inventory: IP без своего веб-сервера → алиас |
| `wifi_ifaces` | `["wlan1", "wlan0"]` | `/api/wifi/scan` (iw dev <iface> scan, перебор до успеха) |
| `traffic_ifaces` | `["end0", "eth0", "wlan1", "wlan0"]` | мониторинг трафика: `monitor.get_system_overview`, `system_routes` (lan/wifi RX/TX; `wlan*` → wifi-счётчики, остальные → lan) |
| `server_ips` | `[…]` | **зарезервирован, кодом сейчас не читается** (задел) |

Интерфейсы сканера задаются единым списком `network.scan_ifaces`
(wired `end0`/`eth0` → wifi `wlan1`/`wlan0`) — покрывает Orange Pi (`end0`)
и X96 (`eth0`) без правки кода; при отсутствии nmap скан честно возвращает
отказ (P1-11). Движок вынесен в `core/discovery.py` (P6).

## Секция `web`

| Ключ | Дефолт | Применение |
|---|---|---|
| `flask_host` | `0.0.0.0` | адрес socketio.run → **рестарт** |
| `flask_port` | `8080` | порт панели → **рестарт** (systemd-юнит/фаервол не меняются автоматически) |

## Секция `events`

| Ключ | Дефолт | Применение |
|---|---|---|
| `retention_days` | `180` | retention событий `events`: чистка при старте сервиса + ежедневный поток (`0` = выкл); `core/events.cleanup_old_events()` |

## Секция `monitoring`

| Ключ | Дефолт | Назначение |
|---|---|---|
| `netdata_url` | `http://127.0.0.1:19999` | локальный netdata (overview) |
| `hosts` | список `{ip, name, netdata}` | вкладка «Мониторинг»: кого опрашивать |

## Секция `weather`

| Ключ | Дефолт | Назначение |
|---|---|---|
| `latitude`, `longitude` | `57.0`, `41.0` | Open-Meteo, `weather-monitor/`, населённый пункт для радиации ЕГАСМРО |
| `timezone` | `Europe/Moscow` | часовой пояс погодных данных |
| `region_name`, `region_code`, `country` | `Иваново`, `ivanovo`, `RU` | название населённого пункта в UI (и в шапке «ближайшие пункты» ЕГАСМРО) |
| `radiation_points` | `3` | сколько ближайших пунктов ЕГАСМРО показывать (1–10) |

## Samba: шары и гостевой доступ

Шары Samba живут в `/etc/samba/smb.conf` (типовая раскладка:
`downloads`/`media`/`share` под `/srv/...` с `valid users = kot` и
`force user = kot`). Панель умеет переключать **гостевой доступ** —
доступ к шарам без пароля из внутренней сети:

- вкладка **«Система» → блок платы → «Гостевой доступ Samba»**
  (переключатель виден только роли `admin`);
- API: `GET /api/samba/guest` (состояние), `POST /api/samba/guest`
  с телом `{"enabled": true|false}` (admin).

Что делает включение (функция `core/samba_guest.py`):

1. Во всех **файловых шарах** (секции с `path`, кроме
   `printers`/`print$`/`homes`/`global`) добавляет `guest ok = yes`.
2. **Временно отключает `valid users`**: строки помечаются
   комментарием `# lan-discovery guest: ` и точно восстанавливаются
   при выключении.
3. Если в `[global]` нет `map to guest = bad user` — прописывает
   (это нужно, чтобы анонимные подключения считались гостем; строка
   после выключения остаётся — на работу с паролем не влияет).

Безопасность применяемого: каждая правка сохраняет бэкап
`/etc/samba/smb.conf.backup-<дата-время>`, новый конфиг сначала
проверяется `testparm -s` и только потом атомарно подменяется;
перезагрузка — `smbcontrol all reload-config` (существующие сессии не
обрываются). Состояние всегда читается из самого smb.conf — отдельный
флаг панель не хранит, ручные правки smb.conf тоже учитываются.

Ограничения: переключатель работает только с `valid users`/`guest ok`;
прочие ручные ограничения (`hosts allow`, `write list`, `admin users`)
не трогает. Гостевые файлы пишутся от владельца шары благодаря
`force user` — при его отсутствии гость получит права `nobody`.
Порт 445: на Orange Pi ufw разрешает его только подсети LAN (см.
[Безопасность](Безопасность.md)); на X96 firewall на хосте нет —
шары видны всем интерфейсам платы, учитывать при подключении чужих
сетей.

## Как перенести на другую сеть/платформу

1. `network.subnet` — подсеть сканирования.
2. `network.self_ips` — IP самой панели (и её интерфейсов).
3. `network.default_hosts`, `known_web_ports`, `web_aliases` — под свою сеть.
4. `monitoring.hosts` — кого мониторить.
5. `scan_ifaces` / `wifi_ifaces` / `traffic_ifaces` — если имена интерфейсов
   отличаются от `end0`/`eth0`/`wlan0`/`wlan1` (`ip -br a` покажет фактические).
6. `web.flask_port` — если 8080 занят (не забыть рестарт).
7. Пути (`/opt/lan-discovery`, `/etc/lan-discovery`, `/srv/media/IPTV`,
   `/etc/transmission-daemon/…`) — захардкожены в коде, правятся только под
   другой структурой установки (не входит в settings.json).

Пример (минимальный override для чужой сети):

```json
{
  "network": {
    "subnet": "10.10.0.0/24",
    "self_ips": ["10.10.0.2"],
    "default_hosts": ["google.com", "10.10.0.1"],
    "known_web_ports": {"10.10.0.2": 8080},
    "web_aliases": {}
  },
  "web": {"flask_port": 8080}
}
```
