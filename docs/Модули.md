# Модули и роуты

## Плагинная система (вкл/выкл, установка зависимостей)

Разделы панели управляются манифестами `modules/<id>/module.json`:

| Поле | Назначение |
|---|---|
| `id`, `name`, `description` | Ключ, название, описание для карточки |
| `type` | `tab` (вкладка меню), `block` (блок внутри вкладки), `app` (плитка приложений) |
| `builtin: true` | Код уже в панели — доступен без установки |
| `url`, `prefixes` | Главная страница и префиксы маршрутов модуля |
| `tab: {title, order}` | Вкладка верхнего меню и её порядок |
| `block: {slot, order, title}` | Для `type: block` — слот вкладки, порядок, заголовок блока |
| `app: {title, icon, category, order}` | Плитка на вкладке «Приложения» (категория = раздел рабочего стола) |
| `page` | Ключ активной вкладки (дефолт = `id`) |
| `help: true` | Рендерить `modules/<id>/help.md` в конце «Справки» |
| `deps: {apt, pip, services, dirs, ports}` | Зависимости — ставятся кнопкой из репозитория ОС |
| `version` | Версия модуля для карточки (1.1; нет — `Unknown`) |
| `source` | Происхождение: `builtin` / `catalog` (1.1) |
| `permissions` | Права модуля — бейдж в карточке (1.1) |
| `hardware` | Аппаратные требования — сверяются с capabilities, несовместимо → статус `incompatible` (1.1) |

- Загрузчик: `core/module_loader.py` — навигация, справка, состояние в `/etc/lan-discovery/modules.json`.
- Админка: `GET /modules` (admin), `POST /modules/<id>/install` (установка deps),
  `POST /modules/<id>/toggle` (вкл/выкл) — `modules/module_manager.py`.
- Выключенный модуль: вкладка скрыта, маршруты из `prefixes` отдают 404 (`before_request`),
  блок/плитка исчезает со своей страницы.
- Справка `/help` собирается динамически: core-разделы + `help.md` только включённых модулей
  (автоматическая TOC-группа «Модули»).
- Рабочий стол `/apps` собирается из ядровых плиток (`CORE_APPS` в загрузчике) + плиток
  включённых модулей (`desktop_categories()`); выключенный модуль прячет свою плитку.
- Активная вкладка (`class="active"`) вычисляется по `request.path` в context_processor.
- Установленные модули: вкладки — inventory, monitoring, torrent, currencies, weather,
  diagnose; плитки — notes, passwords, filemanager, radio, player, camera, terminal, nettools,
  wifianalyzer, disks, downloads, bluetooth, dlna, upnp, portscan.

## Статусы модулей (1.1, STEP 8)

`GET /modules` показывает **один** semantic-бейдж состояния на модуль —
вычисляет `core/module_loader.py::compute_status()`:

| Приоритет | Статус | Когда |
|---|---|---|
| 1 | `incompatible` | `hardware` из `module.json` не проходит по capabilities |
| 2 | `requires-hardware` | нужны неизвестные/отсутствующие устройства |
| 3 | `requires-dependency` | не установлены apt/pip из `deps` |
| 4 | `error` | последняя установка/включение упала |
| 5 | `disabled` | выключен в `modules.json` |
| 6 | `active` | включён, маршруты отдают 200 |
| 7 | `available` | включён, но не отвечает/не определён |
| 8 | `unknown` | нет данных |

- Статус `installed` не используется (в 1.0 он маскировал реальную готовность).
- Поиск отсутствующих apt-пакетов — одним `dpkg-query`-батчем (кэш 60 с),
  полный контекст — `status_context()` (кэш 30 с).
- Страница: `/modules` + JSON `GET /api/...` контекста статуса;
  версия/source/permissions/hardware — из `module.json` (см. выше).

## Роли (1.1, STEP 9)

Профили модулей — комплекты вкл/выкл «под задачу» (страница `GET /roles`,
admin; JSON `GET /api/roles`, применение `POST /roles/<id>/apply`):

| Профиль | Состав |
|---|---|
| `default` «Полный» | все модули панели (`"*"`) |
| `media` «Медиацентр» | torrent, dlna, player, radio, downloads, upnp, sys-iptv |
| `network` «Сеть и наблюдение» | inventory, monitoring, nettools, wifianalyzer, bluetooth, disks |

- **Всегда включён** (не выключается ни одной ролью): `sys-board`,
  `sys-network`, `sys-power`, `sys-settings`, `sys-users`, `sys-db`.
- Применение (`core/roles.py::apply_role`): compat-check через
  `compute_status` — несовместимые/неустановленные модули **пропускаются**
  (skipped), `installed`-флаг не поднимается.
- Состояние активного профиля — `/etc/lan-discovery/roles.json`
  (нет файла → `default`).
- Роуты — `modules/module_manager.py`; реализация — `core/roles.py`.

## Возможности платформы (1.1, STEP 7)

Hardware-снимок с явной достоверностью (`reliability`:
`measured` / `unverified` / `unknown`): архитектура и модель платы,
термозона, накопители, сеть, наличие системных инструментов
(`TOOL_PROBES`). `absent` фиксируется только после неудачного поиска —
иначе `unknown`.

- Сбор — `core/capabilities.py::collect()`; страница `GET /capabilities`,
  JSON `GET /api/capabilities`.
- Потребители: модули со `hardware`-требованиями (см. «Статусы»),
  карточка возможностей на `GET /about` и шапка `/api/dashboard`
  (`core/dashboard.py` — единый агрегат для поллера: система, health,
  устройства, события; один запрос вместо `api/status ×2`).

## Тип `block` — блоки внутри вкладок

Блок — карточка/секция, вставляемая во вкладку через **слот**. Шаблон блока —
`modules/<id>/block.html` (partial), подключается циклом:

```jinja
{% for b in blocks_for("currencies") %}{% include b.template %}{% endfor %}
```

- `blocks_for(slot)` — `core/module_loader.py::block_items(slot)`: возвращает включённые
  блоки слота, отсортированные по `order`; передаётся в шаблоны через context_processor.
- Поиск partials — `ChoiceLoader` в `app.py`: сначала `templates/`, затем `modules/`
  (поэтому `include "curr-fiat/block.html"` работает напрямую).
- Манифест блока **не должен** содержать `url` — иначе `disabled_prefixes()` погасит
  родительскую вкладку целиком при выключении блока.
- Активные слоты: `currencies` (валюты) и `system` (Система).
  - `currencies`: `curr-fiat`, `curr-crypto`, `curr-precious`, `curr-industrial`, `curr-recycling` (+ядро);
  - `system`: `sys-board`, `sys-emmc`, `sys-db`, `sys-network`, `sys-clone`, `sys-iptv`,
    `sys-power`, `sys-settings`, `sys-users`.
- В `system.html`/`currencies.html` остался только заголовок и цикл по слоту; скрипты
  блока (settings/users) лежат внутри его partial — вместе с блоком он и выключается.

## Каталог модулей из GitHub

Внешние модули ставятся с публичного репозитория-каталога
**[Lan-discovery-modules](https://github.com/kotmartovskiy/Lan-discovery-modules)**
(секция «Каталог модулей» на `GET /modules`):

| Роут | Описание |
|---|---|
| `POST /modules/catalog/refresh` | Перечитать `index.json` (кэш 5 минут) |
| `POST /modules/<id>/catalog/install` | Установить модуль из каталога |
| `POST /modules/<id>/catalog/update` | Обновить (только для модулей из каталога) |
| `POST /modules/<id>/catalog/remove` | Удалить (встроенные — нельзя) |

- Реализация: `core/module_catalog.py`.
  1. `index.json` качается с `raw.githubusercontent.com/<repo>/<branch>/`;
  2. файлы модуля распаковываются из tarball ветки (`codeload.github.com`) в
     `modules/<id>/` — с защитой от path traversal, максимум 500 файлов,
     атомарной записью (`.new` → rename) и наличием `module.json` в архиве;
  3. в state пишется `source: "catalog"`, модуль включается.
- Настройки (необязательно) — `modules_catalog: {repo, branch, token}` в
  `/etc/lan-discovery/settings.json`; по умолчанию `kotmartovskiy/Lan-discovery-modules@main`.
- Формат каталога: `index.json` (список `id/name/description/type/slot/version`) +
  каталог `<id>/` с манифестом и файлами — см. README репозитория.

|---|---|
