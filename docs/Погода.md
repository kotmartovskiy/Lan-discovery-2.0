# Погода и оповещения

В панели две независимые вещи: **страница погоды** внутри основного приложения и **отдельное приложение-прототип** `weather-monitor/`.

## 1. Погода в панели — `/weather`

### Откуда данные

Данные **не качаются самим Flask-приложением** — их собирают systemd-таймеры и складывают в `devices.db`:

| Источник | Расписание | Куда пишет |
|---|---|---|
| `/usr/local/sbin/weather-update.py` (`weather-update.timer`) | каждые **15 минут** (+2 мин после загрузки) | `weather_observations`, `weather_hourly`, `weather_daily`, `weather_forecast` |
| там же: информер **meteoinfo.ru** (POST-код региона) | каждые **15 минут** | `weather_alerts` (строка `id=1`) |
| там же: **37.mchs.gov.ru** (стормовые/экстренные) | каждые **15 минут** | `mchs_alerts` (строка `id=1`) |
| `/opt/lan-discovery/env_data.py` (`env-data.timer`) / дубль 2.0: `/usr/local/sbin/env_data_2.py` (`env-data-2.timer`) | каждые **4 часа** | UV, качество воздуха, радиация (ЕГАСМРО) → `env_data` |

> ✅ **Восстановлено на X96 Max 30.09.2026:** таймеры `weather-update.timer`
> (каждые 15 минут) и `env-data.timer` (каждые 4 часа) установлены и активны,
> скрипт `weather-update.py` лежит в `/usr/local/sbin/`.
>
> ✅ **Оповещения восстановлены 01.10.2026:** в `weather-update.py` перенесены
> фетчеры meteoinfo.ru (гидромет-информер) и 37.mchs.gov.ru (раньше они
> работали только в легаси-скрипте на Orange Pi, из-за чего на X96
> предупреждения зависли на данных от 28.09.2026). Ридер дополнительно
> защищён от устаревания: `weather_alerts` показываются не старше 24 часов,
> МЧС-статьи без разбираемой даты окончания — не старше 3 дней по
> `published_at`; просроченные даты `weather_forecast` удаляются при каждом
> обновлении, а ридер берёт только `forecast_date >= сегодня`.
> Скрипты продублированы в `deploy/` репозитория.
>
> ✅ **Радиация — ЕГАСМРО с 04.10.2026:** `env_data.py` ходит в open-data API
> ЕГАСМРО (`egasmro.ru`, сессионная цепочка `curdata → index.php →
> getParams.php → getData.php`, иначе 403) и выбирает **ближайшие пункты
> к населённому пункту** из `settings.weather` (`latitude`/`longitude`,
> `region_name`; сколько пунктов — `radiation_points`, дефолт 3). Для каждого
> пункта считаются расстояние (haversine) и направление (16 румбов); в БД
> пишутся `radiation` (µSv/h ближайшего пункта), `radiation_level`
> (Норма ≤0.2 / Повышенный ≤0.5 / Высокий ≤1.0 / Опасный) и JSON
> `radiation_points` (для колонки «Среда»). При недоступности источника
> показываются прошлые данные — у каждой точки своя дата замера.
> `env_data_2.py` для панели 2.0 — sed-копия того же скрипта (меняется
> только путь `DB` → `/opt/lan-discovery-2.0/devices.db`).

API-источник — **Open-Meteo** (`https://api.open-meteo.com/v1/forecast`), координаты и таймзона берутся из конфига:

```jsonc
// /etc/lan-discovery/settings.json
{
  "weather": {
    "latitude": 56.997,
    "longitude": 41.008,
    "timezone": "Europe/Moscow",
    "interval_minutes": 30
  }
}
```

Фолбэк-конфиг — `/etc/lan-discovery/weather.json`.

**Запасной эндпоинт** (с 30.09.2026): если основной `api.open-meteo.com`
недоступен (такое случалось — хост `94.130.142.35` перестал отвечать), скрипт
делает по 2 попытки на каждый URL с паузой 5 секунд и переходит на
`https://ensemble-api.open-meteo.com/v1/ensemble?models=icon_seamless` —
формат полей `current/hourly/daily` там идентичен (поля с суффиксом
`_memberNN` — члены ансамбля, базовые ключи без суффикса используются как есть).
В журнале видно, какой источник сработал: `=== WEATHER UPDATE OK ... (источник: ensemble)`.

### Что отдаётся

| Роут | Содержимое |
|---|---|
| `GET /weather` | Текущая погода, почасовой на сегодня/завтра, прогноз на день, предупреждения МЧС |
| `GET /api/weather-status` | Короткий статус для шапки панели (обновляется вместе с `/api/status`) |

Коды погоды и направления ветра (`weather_code_name`, `wind_direction_name`) переводятся в человекочитаемый русский, время — `UTC+3` / `Europe/Moscow`.

### Диагностика

```bash
systemctl list-timers | grep weather       # weather-update.timer + env-data.timer должны быть активны
journalctl -u weather-update.service -n 30 --no-pager   # ищите WEATHER ALERT OK / MCHS ALERT OK
/opt/lan-discovery/venv/bin/python -c "import sqlite3; print(sqlite3.connect('/opt/lan-discovery/devices.db').execute('select max(timestamp) from weather_observations').fetchone())"
```

> CLI `sqlite3` на X96 не установлен — запросы удобнее делать через python.

Если на странице пусто — почти всегда виноват таймер/сеть, а не веб-интерфейс: проверьте, что `weather-update.timer` активен и `weather_observations` не пустая.

## 2. Отдельное приложение — `weather-monitor/`

Самостоятельный Flask-проект для отладки и экспериментов с погодными данными (в репозитории, но **не** входит в основную панель).

- `app.py` — Flask на **порту 5000** (`debug=True`);
- `fetcher.py` — сбор данных: Open-Meteo (прогноз), Open-Meteo Air Quality (качество воздуха), парсинг через `BeautifulSoup`;
- `scheduler.py` — `apscheduler` (BackgroundScheduler) вместо systemd;
- `database.py` — собственный SQLite `weather-monitor/weather.db`;
- `templates/weather.html`, `static/style.css` — свой интерфейс.

Запуск:

```bash
cd weather-monitor
pip install -r requirements.txt   # flask, requests, beautifulsoup4, apscheduler
python app.py                     # http://localhost:5000
```

> `weather.db` и `__pycache__` в git не попадают (`.gitignore`).
