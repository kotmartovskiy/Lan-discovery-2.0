# Установка и развёртывание

## Требования

- **Чистая установка:** Debian 11+/Armbian (ARM64/AMD64), root, сеть до
  apt/pypi, Python 3.9+ (проверяется install.sh)
- **Текущая развёртывание (боевая):** X96 Max (Armbian/Debian, ARM64,
  hostname `armbian`); панель на `192.168.3.243`
- Python 3.10+ (в проде — виртуальное окружение `/opt/lan-discovery/venv`, Python 3.11)
- root-доступ по SSH (`root@192.168.3.243`, пароль `1234`)
- Порт `8080` свободен

> Прежний хост — Orange Pi Plus (`192.168.3.234` / WiFi AP `192.168.3.235`) — с 28.09.2026
> выведен из эксплуатации (кабель отвалится, сейчас не отвечает).

## Быстрая установка на чистую машину (`install.sh`)

Один скрипт доводит чистую систему до рабочего состояния. Код должен быть
распакован в каталог (из архива/копии с существующей установки; приватный
git-репозиторий — `git clone` с токеном):

```bash
cd <каталог-с-кодом>
sudo ./install.sh
```

Что делает (каждый шаг идемпотентен, повторный запуск безопасен):

| Шаг | Действие |
|---|---|
| preflight | python3 ≥ 3.9, наличие `app.py`/`requirements.txt`, root при необходимости |
| code | если запуск из другого каталога — копирует код в `--prefix` (существующий `app.py` **не** перезаписывает — обновления см. ниже) |
| deps | `apt-get install` недостающих: nmap traceroute dnsutils iw bluez smartmontools ffmpeg mpv python3-venv |
| venv | `python3 -m venv` + `pip install -r requirements.txt` |
| config | если нет `/etc/lan-discovery/settings.json` — создаёт базовый (subnet/self_ips автоопределены из интерфейсов) |
| db | `init_db_schema()`: миграции по `user_version`, ensure-таблицы, retention событий |
| unit | шаблон `deploy/lan-discovery.service` → `/etc/systemd/system` (ExecStart под prefix) → `daemon-reload` + `enable --now` |
| health | ждёт `http://127.0.0.1:8080/api/health` до 60 с, иначе ошибка с подсказкой журнала |

Флаги:

```bash
sudo ./install.sh --dry-run              # только показать план, ничего не менять
sudo ./install.sh --skip-apt             # пакеты уже установлены
sudo ./install.sh --no-enable            # не делать systemctl enable --now
sudo ./install.sh --prefix DIR           # куда ставить (default /opt/lan-discovery)
sudo ./install.sh --unit-dir DIR         # куда класть юнит (default /etc/systemd/system)
```

**Первый вход:** `http://<ip>:8080` → `admin` / `1234` → сразу сменить
пароль (вкладка «Система» → пользователи).

> Внимание: `--prefix` изолирует код/venv/юнит **и БД** — devices.db
> берётся из `core.config` (каталог кода, env `LAN_PREFIX` — явный
> override). `/etc/lan-discovery/{settings,users}.json` — системные (§20)
> и общие для всех установок хоста: вторая панель рядом требует
> изоляции (bind-mount в юните, как стенд 2.0, либо отдельный хост).

## Ручная установка

```bash
cd /opt/lan-discovery
python3 -m venv venv && venv/bin/pip install -r requirements.txt
venv/bin/python -c "import py_compile; py_compile.compile('app.py', doraise=True)"   # синтакс-проверка
```

Зависимости (`requirements.txt`): Flask, Flask-SocketIO, Flask-WTF, bcrypt, requests, beautifulsoup4, schedule.

## Структура на сервере

| Путь | Назначение |
|---|---|
| `/opt/lan-discovery/app.py` | Точка входа: инициализация Flask/CSRF, фон (schedule), регистрация модулей, main |
| `/opt/lan-discovery/modules/` | Роуты разделов: auth, devices, system, network, media, weather, monitoring, inventory, core, module_manager + модули-компоненты (`curr-*`, `sys-*`, `notes`, `radio`…) |
| `/opt/lan-discovery/core/` | `module_loader.py` (манифесты, навигация, справка), `module_catalog.py` (каталог модулей из GitHub) |
| `/opt/lan-discovery/venv/` | Виртуальное окружение (Python 3.11) |
| `/opt/lan-discovery/templates/` | Jinja2-шаблоны (`base.html` — каркас с нижней панелью статуса) |
| `/opt/lan-discovery/devices.db` | SQLite: `devices`, `weather_*`, `currency_*`, `events`, `device_inventory`… |
| `/etc/lan-discovery/` | `users.json`, `settings.json`, `secret.key`, `iptv-playlists.json`, `modules.json`, `notes/`, `secrets/` |
| `/usr/local/sbin/` | `backup-db.sh` — копия `devices.db` (на прежнем хосте здесь же были `update-iptv*.sh`, `weather-update.py`, `backup-emmc.sh`) |
| `/srv/backup-db/` | Копии `devices.db` (ротация 14 дней) |

## systemd

`/etc/systemd/system/lan-discovery.service`:

```ini
[Unit]
Description=LAN Discovery Web Panel
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=/opt/lan-discovery/venv/bin/python /opt/lan-discovery/app.py
Restart=always
RestartSec=5
User=root

[Install]
WantedBy=multi-user.target
```

```bash
systemctl enable --now lan-discovery
systemctl status lan-discovery
journalctl -u lan-discovery -f
```

### Зависимость от HDD (обязательно при `nofail` в fstab)

Если `/srv` (HDD) прописан в `fstab` с `nofail`, он монтируется **после**
`local-fs.target` — сервисы успевают стартовать по пустой папке (Transmission
падает в «No data found», minidlna строит пустой индекс). Лечится drop-in'ами:

```bash
mkdir -p /etc/systemd/system/transmission-daemon.service.d \
         /etc/systemd/system/minidlna.service.d \
         /etc/systemd/system/lan-discovery.service.d

printf '[Unit]\nRequiresMountsFor=/srv/downloads\n' \
  > /etc/systemd/system/transmission-daemon.service.d/hdd.conf
printf '[Unit]\nRequiresMountsFor=/srv/media /srv/downloads\n' \
  > /etc/systemd/system/minidlna.service.d/hdd.conf
printf '[Unit]\nAfter=srv.mount\n' \
  > /etc/systemd/system/lan-discovery.service.d/hdd.conf

systemctl daemon-reload
systemctl restart transmission-daemon minidlna
```

Подробности и диагностика — в [Полезные-команды](Полезные-команды.md).

### Периодические задачи (таймеры)

| Таймер | Период | Что делает |
|---|---|---|
| `backup-db.timer` | ежедневно в **03:30** | `/usr/local/sbin/backup-db.sh` → SQLite-бэкап `devices.db` в `/srv/backup-db`, ротация 14 дней; карточка и восстановление — на вкладке «Система» («🗄 Backup БД») |

Остальные периодические задачи выполняет само приложение (фоновый поток `schedule`
в `app.py`): курсы валют — раз в 6 часов, цены переработки — раз в сутки; погода и
обновление IPTV — вручную из вкладок панели. На прежнем хосте дополнительно
работали `weather-update.timer` (15 мин), `env-data.timer` (4 ч), `update-iptv.timer`
(04:15) и `backup-emmc.timer` (04:00) — на X96 Max они не установлены
(eMMC-бэкап запускается вручную со вкладки «Система» и **не выполняется** при
загрузке с SD-карты или без HDD).

```bash
systemctl list-timers --all | head -20
systemctl start backup-db.service     # разовый запуск бэкапа БД вручную
```

## Деплой изменений

### Автоматически

```bash
python deploy.py
```

Скрипт: подключается по SSH → создаёт бэкап `app.py.backup-<timestamp>` → заливает файл через SFTP → `py_compile` → `systemctl restart lan-discovery` → печатает статус сервиса.

### Вручную (регламент, обязательный)

1. Бэкап:
   ```bash
   cp /opt/lan-discovery/app.py /opt/lan-discovery/app.py.backup-$(date +%Y%m%d-%H%M%S)
   ```
2. Правка файла (SFTP/`remote_edit.py`).
3. Проверка синтаксиса:
   ```bash
   python3 -c "import py_compile; py_compile.compile('/opt/lan-discovery/app.py', doraise=True)"
   ```
4. Рестарт:
   ```bash
   systemctl restart lan-discovery
   ```

> ⚠️ **Нельзя** перезапускать сервис во время клонирования SD (`dd`) — процесс будет убит.

## Проверка после установки

```bash
systemctl status lan-discovery                      # active (running)
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/login   # ожидаем 200
curl -s http://localhost:8080/api/health            # db.status=ok, user_version=2
```

В браузере: `http://<ip>:8080` → страница входа → `admin` / `1234` →
**сменить пароль**.

cd /opt/lan-discovery && git pull origin main && systemctl restart lan-discovery
